## Research Findings: Current State of A2A (Feb 2026)

### What is A2A?
The **Agent2Agent (A2A) protocol** is an open standard (now under the Linux Foundation, originally from Google) for communication and collaboration between agents. It supports:
- **Agent discovery** via Agent Cards (`.well-known/agent.json`)
- **Message-based communication** between agents
- **Long-running tasks** with continuation tokens
- **Cross-platform interoperability** — the key differentiator from MCP
- **Spec:** https://a2a-protocol.org/latest/

### A2A vs MCP
| Capability | MCP | A2A |
|---|---|---|
| **Use case** | Tool/data access | Agent-to-agent communication |
| **Orchestration** | Host controls everything | Each agent has own chain-of-thought |
| **Multimodality** | Host must support | Agents advertise media types |
| **Multi-turn** | Host manages context | `contextId` across agents |
| **Best for** | Internal tool integration | Cross-platform/cross-org agents |

**Key insight:** Use MCP for internal tools/data; use A2A for cross-platform agent integration.

### A2A in Microsoft Foundry (Preview)
**Status:** Public Preview — documented and functional  
**Docs:** https://learn.microsoft.com/azure/ai-foundry/agents/how-to/tools/agent-to-agent

**How it works in Foundry:**
1. Create an **A2A Connection** in Foundry portal (Tools → Connect tool → Custom → Agent2Agent)
2. Use `A2ATool` with `project_connection_id` to add to an agent
3. Supports Python, C#, TypeScript, REST API (not Java yet)
4. Auth: key-based, Entra ID, or none

**Two integration modes:**
- **A2A Tool** — Agent A calls Agent B; Agent A keeps control, summarizes B's response
- **Workflow** — Agent A delegates; Agent B takes full control

**Python SDK:**
```python
from azure.ai.projects.models import A2ATool

tool = A2ATool(project_connection_id=a2a_connection.id)
agent = project_client.agents.create_version(
    agent_name="MyAgent",
    definition=PromptAgentDefinition(
        model=model_name,
        instructions="You are a helpful assistant.",
        tools=[tool],
    ),
)
```

### A2A in Copilot Studio (Preview)
**Status:** Public Preview  
**Docs:** https://learn.microsoft.com/microsoft-copilot-studio/add-agent-agent-to-agent

**How it works in Copilot Studio:**
1. Go to Agents page → Add an agent → Connect to external agent → **Agent2Agent**
2. Enter the A2A agent's **endpoint URL** (not the agent card URL)
3. Copilot Studio auto-discovers the agent card from `.well-known/agent.json`
4. Select authentication method
5. Done — the A2A agent is now available to the orchestrator

**Other agent connection types in Copilot Studio:**
- Child agents (internal)
- Other Copilot Studio agents (same environment)
- Microsoft Foundry agents (via Foundry project endpoint + Agent ID)
- Fabric Data agents
- Microsoft 365 Agents SDK agents
- **A2A protocol agents** ← This is the cross-platform connector

### Microsoft Agent Framework + A2A (Preview)
**Status:** Preview packages available  
**Docs:** https://learn.microsoft.com/agent-framework/integrations/a2a

**Expose your agent via A2A (C#/.NET):**
```csharp
// NuGet: Microsoft.Agents.AI.Hosting.A2A.AspNetCore
var pirateAgent = builder.AddAIAgent("pirate", instructions: "You are a pirate.");
app.MapA2A(pirateAgent, path: "/a2a/pirate", agentCard: new() {
    Name = "Pirate Agent",
    Description = "An agent that speaks like a pirate.",
    Version = "1.0"
});
```

**Connect to an A2A agent (Python):**
```python
# pip install agent-framework-a2a --pre
from agent_framework.a2a import A2AAgent

async with A2AAgent(name="remote", url="https://a2a-agent.example.com") as agent:
    response = await agent.run("What can you do?")
```

## Answers to Ricardo's Questions

### Q1: Deploying Foundry Agents with A2A Protocol
**Yes, this is now supported in preview.** Two approaches:

1. **Foundry agent as A2A client** — A Foundry agent uses the `A2ATool` to call an external A2A-compliant agent
2. **Foundry agent as A2A server** — Use Hosted Agents + Microsoft Agent Framework to expose a Foundry-backed agent with an A2A endpoint

For the workshop, the most relevant scenario is:
- Build an agent in Foundry → expose it via A2A → connect it from Copilot Studio via the A2A connector
- OR: Foundry agent calls external A2A agents as tools

### Q2: Non-Microsoft Agents (Google, OpenAI, etc.) via A2A
**Yes, this is the entire point of the A2A protocol.** Since A2A is an open standard:

1. **Google ADK** — Google's Agent Development Kit natively supports A2A
2. **LangChain / LangGraph** — A2A server adapters exist
3. **CrewAI** — Community A2A adapters available
4. **OpenAI** — Can build an A2A-compliant server around any OpenAI-based agent
5. **Any framework** — If you can serve HTTP + implement the A2A message format, it works

**Integration path:**
1. Build a non-MSFT agent (e.g., Google ADK, LangGraph, raw OpenAI)
2. Expose it as an A2A server (HTTP endpoint + `.well-known/agent.json`)
3. Connect it to Copilot Studio via the A2A connector
4. The orchestrator in Copilot Studio can now call it alongside Fabric, Foundry, and other agents
